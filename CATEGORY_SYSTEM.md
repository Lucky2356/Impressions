# Система категорий

Категории — одна из центральных функций приложения (§7). Это полноценная древовидная структура произвольной вложенности, отдельная для каждого профиля.

## 1. Дерево категорий

Пример:

```
Продукты
└── Колбасы
    └── Папа может   ← это ОБЪЕКТ/запись, а не категория
```

- «Продукты» — корневая категория;
- «Колбасы» — подкатегория;
- «Папа может» — конечный объект. Конечный продукт **не** моделируется как категория.

Отображение пути в интерфейсе: `Продукты / Колбасы / Папа может`.

Модель хранения — adjacency list + materialized path (`parentId` + `path` + `level`). Обоснование — в `DATA_MODEL.md §3`.

## 2. Основная и дополнительные категории (§7.2)

- Одна **основная** категория (`entry_categories.isPrimary = true`).
- Любое число **дополнительных** категорий.
- **Теги** — отдельный механизм (свободные метки без вложенности). Категории и теги — разные сущности; их нельзя смешивать.

Основная категория остаётся крошками — иерархия делает разницу очевидной без
объяснений: путь один, а полок, на которых лежит запись, может быть несколько.
Дополнительные показываются чипами «Ещё в: …» в карточке записи, свёрнутой
ссылкой в форме и тонкой пометкой на карточке в списке ветки, если запись
попала сюда не основной категорией.

Счётчик ветки считает **все** связи, а не только основные, — поэтому подпись
говорит «12 записей в ветке», а не «12 записей здесь».

Пример:

```
Основная категория:  Продукты / Колбасы
Дополнительные:      Для завтрака, Покупаем часто, Нравится папе
```

## 3. Возможности дерева (§7.1)

Создание корневых/под-/под-под-категорий, переименование, оформление (значок,
цвет, описание, обложка), перемещение в другую ветку, изменение порядка,
архивирование, восстановление, объединение веток, перенос подкатегорий и
записей между ветками, массовое назначение, выбор нескольких категорий для
записи. Поддержка ≥10 уровней (технический максимум 20).

Экран категорий **один**: слева навигатор-дерево, справа страница выбранной
ветки. Прежние два режима — «полки» и «дерево» — ходили по одному и тому же
дереву по-разному, а одно нажатие в полках давало три разных исхода в
зависимости от того, есть ли у категории подкатегории.

Перетаскивание: ветку — на место в дереве (три зоны на строке: перед, внутрь,
после), запись — в ветку. На Windows захват сразу, на Android — долгим
нажатием: мгновенный захват сделал бы дерево непрокручиваемым. Отклонённая
зона не подсвечивается вовсе — «нельзя» должно быть видно до броска. Всё то же
доступно из контекстного меню и с клавиатуры: экранный диктор не перетаскивает.

Объединение веток необратимо, поэтому спрашивается до, а не предлагается
«Вернуть» после. Записи, лежавшие в обеих ветках, не задваиваются: связь
источника удаляется до того, как целевая становится основной, — иначе у записи
на мгновение оказалось бы две основные категории.

## 3.1. Оформление ветки

Цвет ветки выводится по правилу:

```
Цвет(ветка) = свой цвет
            ?? цвет ближайшего предка, у которого он задан
            ?? цвет по первому сегменту path (корню ветки)
```

Наследование, а не свой цвет на каждый узел: иначе «Продукты», «Колбасы» и
«Варёные» получили бы три несвязанных цвета, и дерево стало бы пёстрым шумом.
`color = null` при этом получает внятный смысл — «как у родителя». Цвет зависит
только от `path`, поэтому не меняется от позиции в списке и от поискового
запроса (до 1.16.0 он брался по индексу строки на экране).

Обложка ветки — закреплённое вложение (`coverAttachmentId`), выбирается из
фотографий записей ветки или из файла.

## 3.2. Тип ветки (§9, §11)

`categories.defaultTypeId` — тип объекта по умолчанию для записей этой ветки.
Форма быстрого добавления берёт тип отсюда и подписывает, из какой ветки он
взят.

До 1.16.0 тип угадывался по совпадению названий категории и типа: правило жило
в коде, нигде не показывалось и не правилось, а форма вынуждена была
объясняться подписью «Тип задаёт набор полей, категория — вашу полку в дереве».
Разовый проход схемы 7 проставил тип тем же правилом — у заведённых раньше
деревьев ничего не изменилось, но теперь это видно и поправимо.

## 4. Защита от циклов (§7.1)

Запрещены:
- циклические ссылки;
- категория как собственный родитель;
- перемещение родителя внутрь своего потомка.

Проверка при перемещении: новый `parentId` не должен принадлежать поддереву перемещаемой категории (проверяется по префиксу `path`). При нарушении операция отменяется, дерево не меняется. Записи при перемещении не теряются (перемещается только узел; связи `entry_categories` сохраняются).

## 5. Хлебные крошки (§7.6)

Путь строится из сегментов `path`. Каждая категория в пути кликабельна. После категорий отображается название объекта: `Продукты / Колбасы / Папа может`. На мобильном длинный путь сокращается (например `Продукты / … / Колбасы`) и полностью раскрывается по нажатию.

## 6. Категории разных профилей (§7.3)

У каждого профиля своё дерево. Категории одного профиля не меняют дерево другого. При импорте дерево профиля обновляется вместе с профилем через revisions:
- новые категории/подкатегории — добавляются;
- переименования и перемещения — сохраняются как новые версии;
- старые категории физически не удаляются;
- локальные настройки отображения сохраняются;
- дубликаты не создаются (сверка по `id` и `contentHash`).

## 7. Перенос записи между профилями (§7.4)

Когда пользователь добавляет чужую запись себе, предлагаются варианты:
1. использовать похожую существующую категорию;
2. создать недостающий путь категорий;
3. выбрать другую категорию;
4. сохранить без категории.

Настройка профиля «При переносе записей»: *предлагать совпадающий путь* (по умолчанию) / *автоматически создавать отсутствующие* / *всегда спрашивать* / *сохранять без категории*. Автокопирование без явного подтверждения при отличающейся структуре не выполняется.

## 8. Поиск и фильтрация (§7.5)

Категории работают во всех разделах: каталог, поиск, главная, сравнение, импорт, экспорт, подборки, массовые операции, история, статистика, резервные копии.

Переключатель **«Показывать записи из подкатегорий»**:
- выкл. — только записи непосредственно в выбранной категории;
- вкл. — вся ветка, включая вложенные.

Показ количества записей (`Продукты — 128`, `Колбасы — 14`); счётчик родителя может включать вложенные записи, что визуально обозначается.

## 9. Импорт/экспорт категорий

Экспортируются: отдельная категория, вся ветка с подкатегориями, либо всё дерево профиля. Сопоставление деревьев разных профилей при переносе — по нормализованному пути (см. §7). Нормализация имени (`normalizedName`) обеспечивает устойчивое сравнение (регистр, пробелы, регистр Unicode).
