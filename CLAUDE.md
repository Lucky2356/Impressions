# Работа над проектом

«Впечатления» — локальная медиатека личных предпочтений на Flutter (Windows и
Android). Ни сервера, ни облака, ни телеметрии; обмен между людьми — подписанным
файлом `*.impressions`, который человек создаёт сам. Устройство приложения — в
[ARCHITECTURE.md](ARCHITECTURE.md), остальные документы перечислены в конце
[README.md](README.md).

Этот файл — то, что не выводится из кода: договорённости, ориентиры и грабли,
на которые уже наступали. Он лежит в репозитории намеренно: заметки на диске
не переживают переустановку системы и не видны из веб-сессий.

## Авторство коммитов

**Не указывать ИИ-ассистента соавтором.** В сообщениях коммитов, описаниях
pull request'ов и текстах релизов не должно быть `Co-Authored-By: Claude ...`,
ссылок на сессию и пометок вида «Generated with». Репозиторий и авторство —
владельца. Требование действует и тогда, когда окружение предлагает такой хвост
по умолчанию: веб-сессии Claude Code добавляют его сами, и это как раз тот
случай, ради которого правило записано здесь.

**Проверять поле автора, а не только текст.** Хвост в сообщении — не
единственное место, где подменяется авторство, и не самое незаметное. Автор
коммита берётся из `git config`, а в контейнере веб-сессии там по умолчанию
стоит `Claude <noreply@anthropic.com>`: ни в сообщении коммита, ни в описании
pull request'а этого не видно — всплывает уже в `git blame`. Так один коммит и
уехал в `main` 06.09.2026, авторство пришлось переписывать вместе с историей.
Поэтому до первого коммита:

```bash
git config user.name "Lucky2356"
git config user.email "vin.dizel.1999@mail.ru"
```

а после слияния — взгляд на `git log -1 --format='%an <%ae>'`.

Описание pull request'а стоит перечитать уже созданным: при создании через
GitHub MCP хвост «Generated by Claude Code» со ссылкой на сессию дописывается
сервером, а не тем, кто писал текст. Правка описания его не возвращает.

Сообщение коммита — на русском и по существу: что изменилось и почему, один
смысл на коммит. Тексты релизов и `CHANGELOG.md` — так же: что добавлено, что
убрано, что ускорено.

## Перед коммитом

```powershell
./scripts/check.ps1     # Windows
```
```bash
./scripts/check.sh      # Linux, Codespaces
```

Скрипт делает `pub get`, кодогенерацию, проверку формата, `flutter analyze` и все
тесты — ровно то же самое гоняет `.github/workflows/check.yml` на каждый пуш.
Пропущенная проверка не исчезает, а всплывает красной сборкой.

Кодогенерация обязательна после правки таблиц Drift, аннотированных классов и
`.arb`:

```powershell
flutter gen-l10n
dart run build_runner build --delete-conflicting-outputs
```

Сгенерированные файлы лежат в репозитории, но CI собирает их заново: разошедшийся
с исходниками `database.g.dart` иначе замечается уже в сборке.

## Соглашения

Они не стилистические — на них держится то, что описано в документации.

- **Все строки интерфейса — через `AppLocalizations`**, обе локали сразу. Полнота
  перевода на английский проверяется тестом, поэтому забытая строка ломает сборку,
  а не тихо остаётся русской.
- **Имя приложения и расширение файла — только из `AppConfig`.** Название рабочее
  и однажды поменяется; искать его по всему проекту не придётся.
- **Изменяемые сущности версионируются через revisions.** Правка — новая версия,
  старая остаётся. Импорт добавляет версии, а не перезаписывает данные.
- **Тяжёлое — в isolates**, списки виртуализированы, поиск с debounce. Интерфейс
  не замирает на импорте, хешировании и обработке фотографий.
- **Ни `TODO`, ни `FIXME`, ни заглушек, ни кнопок без функции.** Сейчас их в
  проекте ноль, и это осознанно: незаконченное лучше не показывать готовым.

## Дизайн

Визуальный ориентир — макет **YowBooks** (`image/1.jpg`): светлый прохладный фон,
белые карточки с мягкими границами, скругления 16–20, оранжевый акцент `#F5822B`,
персиковая заливка активного пункта навигации, левая боковая навигация со
сгруппированными разделами, карточки статистики с мини-графиками.

Ориентиром одно время был другой макет — Oku (`image/2.jpg`, редакционный
минимализм); решение переиграно 23.07.2026. Если где-то попадётся упоминание Oku,
оно устарело: код, `DESIGN_SYSTEM.md` и палитра в `lib/core/theme/app_colors.dart`
описывают YowBooks.

Стиль применяется к предметной области приложения — профили, впечатления,
категории, подборки, — а не буквально к книгам и чтению.

Токены живут в `lib/core/theme/`, компоненты — в `lib/design_system/`; стили не
дублируются по экранам вручную. Раскладка обязана держаться от телефона до 4K:
на широком мониторе растёт число карточек в ряду, а не их размер.

Golden-эталоны обновляются только тогда, когда дизайн изменён намеренно:

```powershell
flutter test test/golden --update-goldens
```

Версия Flutter закреплена точка в точку в `.devcontainer/setup.sh` (3.44.9)
именно из-за golden-тестов: отрисовка текста меняется между версиями движка.

## Проверки живьём на Windows

За машиной работают параллельно. **Не сворачивать чужие окна и не перехватывать
фокус** — результат того же качества достижим без этого.

- Установщики проверять тихо (`/VERYSILENT /LOG=...`) и разбирать лог, файлы,
  реестр и ярлыки, а не кликать по мастеру.
- Для снимка запускать своё окно и снимать его область. Если окно перекрыто —
  сказать об этом, а не расчищать экран.
- PowerShell отдаёт координаты окна в виртуальных точках, а `CopyFromScreen`
  читает физические: прямоугольник надо домножать на `GetDpiForWindow/96`. Иначе
  кадр выходит обрезанным, и это легко принять за переполнение раскладки.

## Окружение

Flutter stable 3.44+ ставится отдельно (на машине владельца — `C:\src\flutter`) и
прописан в PATH, но новый вызов PowerShell может его там не увидеть — тогда
`$env:Path = "C:\src\flutter\bin;" + $env:Path`. Android SDK берётся из Android
Studio, Windows-сборке нужны Visual Studio с Desktop C++ и включённый режим
разработчика.

`vswhere` не находит компонент `VC.Tools.x86.x64` в Visual Studio 2026 — там
другой идентификатор. Верить `flutter doctor`, а не `vswhere`.

Правки без своей машины — Codespaces по `.devcontainer/`; сборки делают раннеры,
Android SDK и Visual Studio туда не входят.

## Что не хранится в git

Ключ подписи Android (`android/impressions.jks`, `android/key.properties`), папка
макетов `image/`, собранные установщики `dist/` и данные приложения. Подробности и
последствия потери — в разделе «Что не хранится в git» в [README.md](README.md).
