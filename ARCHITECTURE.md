# Архитектура приложения «Впечатления»

> Рабочее название временное, хранится в `lib/core/config/app_config.dart`.

## 1. Обзор

«Впечатления» — полностью локальное кроссплатформенное приложение (Windows, Android; архитектура готова к iOS) для хранения личных предпочтений, впечатлений, рекомендаций и коллекций. Никакого сервера, облака, регистрации, аналитики, телеметрии и обязательного интернета. Обмен данными между людьми — только через подписанный файл профиля `*.impressions`.

## 2. Технологический стек

| Слой | Технология |
| --- | --- |
| UI | Flutter (stable 3.44+), Material 3 как техническая основа, собственная дизайн-система |
| Состояние | Riverpod |
| Навигация | GoRouter |
| Модели | Freezed + json_serializable (при недоступности — ручные immutable-классы) |
| БД | SQLite через Drift |
| Идентификаторы | uuid (v4) |
| Локализация | flutter gen-l10n (ARB), основная локаль — ru |
| Криптография | cryptography (Ed25519 подписи, AES-GCM шифрование пакетов), crypto (SHA-256) |
| Файлы | file_selector, path_provider, archive |
| Изображения | image (обработка без сети), image_picker (камера/галерея Android), desktop_drop (drag-and-drop Windows) |

Все пакеты поддерживают Windows и Android. Web как основная платформа не используется.

## 3. Слои

```
UI (features/*)                 экраны и виджеты, только Russian через l10n
  │  Riverpod providers
Application (репозитории)        бизнес-операции, транзакции, версионность
  │
Data (data/db, data/import_export, data/backup)
  │  Drift DAO
SQLite + файловое хранилище вложений
```

- **`lib/core`** — конфигурация (`app_config.dart`), тема и дизайн-токены, локализация, утилиты (нормализация строк, хеши, uuid).
- **`lib/design_system`** — переиспользуемые компоненты и debug-галерея.
- **`lib/data/db`** — таблицы Drift, DAO, миграции.
- **`lib/data/repositories`** — репозитории поверх DAO: профили, устройства, объекты, записи, категории, revisions, подборки, вложения, связи, рекомендации.
- **`lib/data/import_export`** — контейнер `.impressions`, подпись, шифрование, безопасный импорт/экспорт.
- **`lib/data/backup`** — резервные копии.
- **`lib/features`** — onboarding, home, catalog, categories, entry, compare, import, collections, settings.
- **`lib/app`** — корневой `App`, роутинг, провайдер темы.

## 4. Ключевые архитектурные принципы

1. **Разделение объекта и мнения (§6).** Общий `object` (фильм, продукт, место) отделён от `profile_entry` (мнение конкретного профиля). Один объект — много записей разных профилей.
2. **Неизменяемые revisions (§18).** Изменяемые сущности (профиль, объект, запись, категория, тип) версионируются. Изменение = новая revision; старые сохраняются. Восстановление = новая revision на основе старой.
3. **Изоляция профилей.** У каждого профиля собственное дерево категорий, свои записи и подборки. Операции одного профиля не меняют данные другого.
4. **Локальные настройки отдельно от передаваемых (§5.3).** Локальное имя/заметки о человеке никогда не экспортируются и не стираются при повторном импорте.
5. **Импорт не перезаписывает напрямую (§18, §20).** Повторный импорт обновляет существующую локальную копию профиля, добавляя новые revisions; дубликаты не создаются; определение профиля — по `profileId` + открытому ключу + подписи.
6. **Тяжёлые операции — вне UI-потока (§29).** Импорт/экспорт, хеширование, обработка фото, перестроение дерева выполняются в isolates; списки виртуализированы; поиск с debounce; данные грузятся пагинированно.
7. **Никаких хардкод-строк UI (§1).** Все тексты интерфейса — через `AppLocalizations`.

## 5. Стратегия дерева категорий

Выбрана комбинация **adjacency list + materialized path** (обоснование — в `DATA_MODEL.md` и `CATEGORY_SYSTEM.md`). Категория хранит `parentId`, `path` (материализованный путь из UUID) и `level`. Потомки/предки/подсчёт по ветке — через префикс `path` и/или recursive CTE. Проверка циклов — при перемещении.

## 6. Потоки данных обмена

Экспорт → подписанный zip-контейнер `*.impressions` (manifest, jsonl-таблицы, вложения, checksums, signature). Импорт → безопасная распаковка во временный каталог, проверки (Zip Slip, лимиты, подпись, checksums), предпросмотр, резервная копия, транзакционное применение, итог. Подробности — в `IMPORT_EXPORT_FORMAT.md` и `SECURITY.md`.

## 7. Карта экранов

- Onboarding → создание первого профиля (генерация ключей) → выбор стартовых типов.
- Home — визуальная главная (§14).
- Catalog — сетка/список/дерево, фильтры и сортировка (§15).
- Категории — дерево с CRUD, перемещением, хлебными крошками (§7).
- Карточка записи/объекта, форма редактирования, быстрое добавление (§11).
- Сравнение профилей (§13).
- Импорт: выбор файла → предпросмотр → результат (§20).
- Подборки (§27), Настройки, История/Обновления (§23).
- Debug-галерея компонентов (только в debug).

## 8. Целевые платформы

- **Windows**: трёхпанельный layout, клавиатура/мышь, hover, контекстные меню, drag-and-drop, горячие клавиши (§4.1).
- **Android**: нижняя навигация, верхний переключатель профиля, FAB, нижние листы, свайпы, системная «Назад» (§4.2).
